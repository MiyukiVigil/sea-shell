# sea-shell on a Lua Hyprland config (0.55+)

Since Hyprland 0.55, the compositor config can be **Lua** (`~/.config/hypr/hyprland.lua`),
and the old hyprlang `.conf` is deprecated — removal is expected around **0.57**. sea-shell
ships both: the classic `sea.conf` / `keybinds.conf` **and** their Lua equivalents
`sea.lua` / `keybinds.lua`. `install.sh` deploys all of them to `~/.config/hypr/sea-shell/`.

> **Only the Hyprland compositor config moves to Lua.** `hypridle` and `hyprlock` keep
> hyprlang `.conf` (per upstream) — so `hyprlock.conf` / `hypridle.conf` are unchanged.

## Using the `.conf` config (Hyprland ≤ 0.56)

Nothing to do — `install.sh` wires a `source =` block into `~/.config/hypr/hyprland.conf`
as always.

## Using the Lua config (Hyprland 0.55+, required at ~0.57)

Your top-level config becomes `~/.config/hypr/hyprland.lua`. Add the sea-shell parts by
`dofile`-ing them (this replaces the `source =` block):

```lua
-- somewhere in ~/.config/hypr/hyprland.lua
local here = debug.getinfo(1, "S").source:sub(2):match("(.*/)") or (os.getenv("HOME") .. "/.config/hypr/")

dofile(here .. "sea-shell/sea.lua")       -- look: general/decoration/animations/layer rules
dofile(here .. "sea-shell/keybinds.lua")  -- all keybinds (descriptions preserved for SUPER+K)

hl.on("hyprland.start", function()
    hl.exec_cmd("qs -c sea-shell")
    hl.exec_cmd("command -v hypridle >/dev/null && exec hypridle")
    hl.exec_cmd("[ -x /usr/lib/hyprpolkitagent/hyprpolkitagent ] && exec /usr/lib/hyprpolkitagent/hyprpolkitagent")
    hl.exec_cmd("sleep 0.5; exec ~/.config/quickshell/sea-shell/sea-wallpaper-restore.sh")
end)
```

`sea.lua` also `pcall(dofile, …)`s `~/.config/hypr/sea-shell/matugen.lua` — the wallpaper
accent override, written by `matugen-accent.sh` alongside `matugen.conf`. Absent/empty is
fine (the default sea-cyan borders stand).

## Converting your existing config

`hyprconf2lua` auto-converts ~90% of a hyprlang file. **Review the output** — it drops bind
descriptions and mangles combined-flag binds, animations, and layer-rule namespaces. Always
validate before switching:

```sh
Hyprland --verify-config -c ~/.config/hypr/hyprland.lua    # must print "config ok"
```

## Flipping / reverting

Hyprland resolves its config **at startup**, checking `hyprland.lua` *before* `hyprland.conf`.
Two things that bite you:

- **`hyprctl reload` cannot switch a running hyprlang session to Lua.** It re-reads the file
  Hyprland booted from. Reloading after moving `hyprland.conf` away just makes Hyprland
  generate a blank default ("you're using an autogenerated config") — do **not** do this.
- You therefore flip by **logging out and back in**, not by reloading. Leave `hyprland.conf`
  in place as the automatic fallback (Lua wins when present; `.conf` loads if Lua is absent).

```sh
# FLIP: put hyprland.lua in place, then LOG OUT and LOG BACK IN (do NOT hyprctl reload).
mv ~/.config/hypr/hyprland.lua.ready ~/.config/hypr/hyprland.lua
#   -> log out / log in; a fresh Hyprland auto-detects hyprland.lua.

# REVERT: from a TTY (Ctrl+Alt+F2) if the Lua session misbehaves, then log back in.
mv ~/.config/hypr/hyprland.lua ~/.config/hypr/hyprland.lua.ready   # (or: rm hyprland.lua)
#   -> Hyprland falls back to the still-present hyprland.conf.
```

The settings UI (keybind add/rebind, lid action) writes to whichever of `keybinds.lua` /
`keybinds.conf` is present, so it keeps working across the flip.
